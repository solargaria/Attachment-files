| 1 | มีแหล่งจำเป็นอย่างน้อยหนึ่งแหล่งให้ RETRIEVAL_FAILED | RETRIEVAL_FAILED |
| 2 | แหล่งจำเป็นทุกแหล่งผ่าน Strict และ FOUND และแหล่งเสริมทุกแหล่งไม่ล้มเหลว | FOUND |
| 3 | ทุกแหล่งในขอบเขต complete และทุกแหล่งไม่พบหลักฐาน และไม่เคยพบ SR | NOT_FOUND |
| 4 | อื่นทั้งหมด (พบหลักฐานบางส่วน หรือแหล่งเสริมล้มเหลว) | PARTIAL |

- หลักฐานจากแหล่ง A ที่ FOUND ห้ามนำไปกลบ RETRIEVAL_FAILED ของแหล่ง B ที่จำเป็น (แถว 1 มาก่อนแถว 2 เสมอ)
- แถว 3 ต้องตรวจทุกแหล่งในขอบเขตตาม R-S-1 ก่อนเสมอ

## 3. กฎ Failure

- **FH-1:** F-1 ถึง F-7, F-9, F-11 ถึง F-14b และ N-2 ให้ RETRIEVAL_FAILED หรือ PARTIAL ห้ามให้ NOT_FOUND ยกเว้นผลสุดท้ายระดับแหล่งตาม R-B-6 (การพยายามแรกล้มเหลวชั่วคราว และการพยายามที่สอง complete โดยไม่เคยพบ SR)
- **FH-2:** ห้ามตอบจากแหล่งอื่นแทนแหล่งจำเป็นที่ล้มเหลว (MH-08)
- **FH-3:** ผลของการพยายามที่ล้มเหลวไม่ใช่ผลสุดท้ายจนกว่า R-B จบ (ดู §4.2)
- **FH-4:** Failure ทุกครั้งบันทึกตาม §5.1
- **FH-5 (มติ Owner 2026-11-25 ตาม WP3 §1.4):** คำตอบที่มีผล RETRIEVAL_FAILED ต้องบอกว่าตรวจไม่ได้ และห้ามใช้ถ้อยคำ "ไม่พบ", "ไม่มี", "ไม่เจอ", "ไม่ปรากฏ", "ไม่เคย" ในทุกประโยคของคำตอบนั้น
- **FH-6 (ตามมติ X และ CR-WP4-001):** Source ที่เคยพบ SR ตอนค้นแล้วตรวจไม่ได้ตอนตอบ (F-7) → RETRIEVAL_FAILED เมื่อเป็นแหล่งจำเป็น และ PARTIAL เมื่อเป็นแหล่งเสริม Evidence ที่ตรวจไม่ได้ไม่ถูกนับเป็น FOUND ป้ายกำกับ UNATTRIBUTED ของกรณีนี้รอ CR-WP4-002 ก่อนใช้งานจริง
- **FH-8 (complete):** Adapter ต้องส่งสถานะหนึ่งใน complete, incomplete, error พร้อมสัญญาณใน §3.1 ผลว่างเป็น NOT_FOUND ได้เฉพาะเมื่อ complete ครบ มิฉะนั้นเป็น F-13 หรือ F-12 ตามลำดับใน §2.1
- **FH-9 (Catch-all):** Error หรือ Exception ที่ไม่ตรงกับ F-1 ถึง F-14b ไม่ว่าเกิดขั้นใด ให้ F-11 และห้าม NOT_FOUND
- **FH-10:** การแบ่งหน้าหรือตัดทอนที่ไม่มีสัญญาณครบ ให้ F-12
- **FH-11:** ไม่มี Adapter ใดคืนผลว่างโดยไม่ส่งสถานะ

### 3.1 สัญญาณ complete ที่ตรวจได้ (MR-03)

Adapter ต้องส่งค่าต่อไปนี้ทุกครั้ง:
- สถานะ (complete / incomplete / error)
- ขอบเขตที่ค้น (รหัสแหล่งและช่วงที่ค้น)
- จำนวนผลที่คืนมา
- ตัวบ่งชี้การตัดทอนหรือแบ่งหน้า (ครบ / ยังไม่ครบ)
- ตัวบ่งชี้การกรองสิทธิ์ (ไม่มีการกรอง / กรองแล้วและระบุจำนวนรายการที่ถูกกรอง)

การจัดประเภทแยกกัน 3 กรณี:
- **incomplete:** Adapter ประกาศว่าผลไม่ครบ → F-12 ไม่สามารถใช้ NOT_FOUND ได้
- **permission-filtered:** Adapter ประกาศว่ามีรายการถูกกรองจากสิทธิ์ และผลว่างหรือไม่ครบเพราะการกรอง → ถือเป็น F-3 สำหรับแหล่งจำเป็น และห้าม NOT_FOUND; สำหรับแหล่งเสริมให้ PARTIAL
- **contract violation:** Adapter ส่งค่าไม่ครบตามรายการข้างต้น หรือส่งค่าขัดกันเอง → F-11

ค่าใดขาดไปโดยไม่ได้ประกาศ ให้ถือว่าไม่ complete ตามกฎ FH-8

### 3.2 ขอบเขตการค้น

- **R-S-1:** ก่อนค้น ระบบกำหนดขอบเขตจาก Coverage Contract (WP1 v1.1 §5.2) ตามประเภท Claim CT-1 ถึง CT-4 แหล่งจำเป็นทุกแหล่งต้องอยู่ในขอบเขตเสมอ
- **R-S-2:** แหล่งจำเป็นที่ยังไม่พร้อม (เช่น SC-1 ก่อน Phase 1) หรือเข้าถึงไม่ได้ ต้องคงอยู่ในขอบเขตและให้ผลตามรหัส F ที่เกี่ยว (F-6 หรือ F-9) ห้ามตัดออกจากขอบเขตเพื่อให้ได้ NOT_FOUND
- **R-S-3:** ขอบเขตที่ใช้ตัดสินต้องถูกบันทึกใน Log (ฟิลด์ L-3) ทุกครั้ง และต้องตรงกับ Coverage Contract ของ CT นั้น

### 3.3 การจับคู่ Evidence Item ข้ามการพยายาม (MR-04)

- ทุก Evidence Item ต้องมี **รหัสอ้างอิงคงที่** (Evidence Item ID) ที่ Adapter ส่งมาพร้อม SR
- การพิจารณาว่า SR ที่พบใน A1 ได้รับการ resolve ใน A2 แล้วหรือไม่ ใช้การจับคู่ด้วยรหัส ห้ามใช้จำนวนรายการ
- ตัวอย่าง: A1 พบรหัส {e1, e2, e3} และ A2 คืน {e1, e2, e4} ถือว่า e3 ยังไม่ resolve → R-B-9 ไม่ว่าจำนวนจะเท่ากัน
- ถ้า Adapter ไม่มีรหัสคงที่ → contract violation ตาม §3.1 → F-11
- บันทึกรหัสของทุก Evidence Item ที่พบในแต่ละ Source-Attempt ใน L-8

### 3.4 Prohibited Terms และเกณฑ์ตรวจจับ (MR-09, Owner อนุมัติ)

**ชุดคำ:** ไม่พบ, ไม่เจอ, ไม่ปรากฏ, ไม่มี, ไม่เคย (และรูปแบบอื่นที่มีความหมายว่า "ไม่มีในการค้น" รอ Catalogue)

**FULL MATCH (แก้ไขตามมติ Owner 2026-11-25):** คำใน §3.4 ปรากฏในข้อความถึงผู้ใช้ตรงตามรูปเต็ม โดยตรวจขอบคำแบบภาษาไทย
- ในคำตอบที่มีผล RETRIEVAL_FAILED: FULL MATCH ในทุกประโยคถูกบล็อก (ตาม WP3 §1.4)
- ในคำตอบผลอื่น: FULL MATCH ถูกบล็อกเฉพาะประโยคที่ยืนยันการค้นสมบูรณ์ เพราะ NOT_FOUND ใช้คำว่า "ไม่พบ" ได้ตามความหมาย

**PARTIAL MATCH:** คำที่อยู่ในรูปใกล้เคียง หรือปรากฏโดยไม่ได้อยู่ในประโยคเกี่ยวกับการค้น
- PARTIAL MATCH ใช้ได้เฉพาะเป็นสัญญาณให้ตรวจทาน (flag) ไม่เปลี่ยนผลระดับคำขอ
- PARTIAL MATCH มีผลเฉพาะกับข้อความที่ Failure ทำให้ตรวจไม่ได้ ห้ามขยายไปยังข้อความที่ผลเป็น FOUND หรือ PARTIAL ตามปกติ

**เกณฑ์ป้องกัน False Positive:**
- มี allowlist ของวลีที่ไม่เกี่ยวกับการค้น (เช่น ไม่มีปัญหา, ไม่มีอะไรต้องกังวล) ที่ไม่ถูกนับ
- ต้องวัด False Positive Rate บนชุดตัวอย่างก่อนนำไปใช้จริง
- **รอ Owner:** ค่าเกณฑ์ FP ที่ยอมรับได้ และขนาดชุดตัวอย่าง

**รันไทม์ (H-26):** ยังไม่ได้ทดสอบจริง

## 4. Retry Policy (ตามมติ R-B)

### 4.1 การจำแนกชนิด

- **ชั่วคราว (Retry ได้):** Timeout เกิน T_attempt, Connection reset, Provider 5xx, Rate-limit ที่ระบุว่ารอแล้วลองได้, Database connection หรือ timeout (F-4)
- **ถาวร (ห้าม Retry):** Permission Error (F-3), Default Deny ตาม §5.2 (F-3), แหล่งเข้าถึงไม่ได้ถาวร (F-9), ID ไม่มี, แหล่งไม่พร้อม (F-6), Request ผิดรูปแบบ, Source ถูกลบ, T_total หมด (F-5), การยกเลิก (F-14a), การตัดการเชื่อมต่อถาวรโดยระบบ (F-14b), Error ที่ไม่รู้จัก (F-11)
- **F-12 และ F-13:** ข้อเสนอให้ถือว่าถาวร ไม่ Retry (รอ Owner ยืนยัน)
- ค่าเริ่มต้นเมื่อไม่รู้จัก: ถาวร ไม่ Retry (รอ Owner ยืนยัน)
- ตาราง mapping Error จริงของ Provider ยังไม่มี ต้องจัดทำก่อนใช้งานจริง

### 4.2 กฎ R-B

- **R-B-1:** Retry ได้ไม่เกิน 1 ครั้งต่อแหล่งต่อคำขอ
- **R-B-2:** Retry เริ่มได้เฉพาะเมื่อเวลาที่เหลือใน T_total พอให้การพยายามเต็มหนึ่งครั้งจบ
- **R-B-3:** ไม่ Retry ความล้มเหลวถาวรตาม §4.1
- **R-B-4:** ผลของการพยายามแรกเป็นผลสุดท้ายทันที ถ้าไม่ได้ Retry (เพราะ R-B-2 หรือ R-B-3) และต้องบันทึกรหัส F ของการพยายามนั้น ยกเว้นกรณี complete ที่ผลว่างและไม่เคยพบ SR ซึ่งให้ผลระดับแหล่งเป็น NOT_FOUND โดยไม่มีรหัส F (L-9 ว่าง) ถ้าการพยายามแรกเป็น complete ที่พบ SR ให้ใช้ผลตาม WP1 v1.1 §5.3
- **R-B-5:** ถ้า Retry เกิดขึ้น ผลสุดท้ายคือผลของการพยายามที่สอง เว้นแต่ R-B-6 หรือ R-B-9 กำหนดเป็นอย่างอื่น
- **R-B-6:** ถ้าการพยายามแรกล้มเหลว (ชั่วคราว) และการพยายามที่สองให้ complete พร้อมผลว่าง **และไม่เคยพบ SR ของเนื้อหานั้นในการพยายามใดเลย** ผลระดับแหล่งคือ NOT_FOUND และการพยายามแรกยังถูกบันทึกเป็นเหตุการณ์ของคำขอ (ผลระดับคำขอตาม §2.1.1)
- **R-B-7:** ถ้าการพยายามที่สองล้มเหลว ผลสุดท้ายคือรหัส F ของการพยายามที่สอง
- **R-B-8:** ถ้าการพยายามทั้งสองให้รหัส F ต่างกัน ผลสุดท้ายคือรหัส F ของการพยายามที่สอง และบันทึกทั้งสองรหัส
- **R-B-9:** ถ้า Evidence Item ใด ๆ ถูกพบในการพยายามใดก็ตาม (รวมถึงที่คืนมาก่อนล้มเหลว) และการพยายามที่สองไม่ resolve Evidence Item ทั้งหมดที่พบได้ครบตามรหัส §3.3 (ไม่คืนเลย, คืนไม่ครบ, หรือล้มเหลว) ผลสุดท้ายของแหล่งจำเป็นคือ RETRIEVAL_FAILED ตามรหัส F-7 ไม่ใช่ NOT_FOUND และแหล่งเสริมให้ PARTIAL (MR-04)
- **ลำดับความสำคัญ:** เมื่อการพยายามแรกพบ Evidence Item แล้วการพยายามที่สองล้มเหลว ให้ใช้ R-B-9 (F-7) เหนือ R-B-7 และ R-B-8 และบันทึกรหัส F ของทั้งสองการพยายามใน L-9
- **R-B-10 (ตารางครบชุดของลำดับการพยายาม):** การพยายามแรกที่ complete จะไม่ Retry (R-B-4) การ Retry เกิดได้เฉพาะเมื่อการพยายามแรกเป็นความล้มเหลวชั่วคราว (สถานะ incomplete หรือ error) ซึ่งอาจคืน Evidence Item บางส่วนมาแล้วหรือไม่ก็ได้ จากนั้นให้เลือกเพียงแถวเดียวตามตารางนี้

| แถว | A1 (ล้มเหลวชั่วคราว) พบ Evidence Item หรือไม่ | A2 | ผลระดับแหล่ง |
|---|---|---|---|
| 1 | ไม่พบ | complete ไม่มี Evidence Item | NOT_FOUND (R-B-6) |
| 2 | ไม่พบ | complete และพบ Evidence Item ใหม่ที่ resolve ได้ครบ (ไม่มีรายการค้างจาก A1 เพราะ A1 ไม่พบ) | ตาม WP4 (FOUND) |
| 3 | ไม่พบ | ล้มเหลวโดยไม่มี Evidence Item | รหัส F ของ A2 (R-B-7, R-B-8) |
| 4 | ไม่พบ | complete resolve ไม่ครบ หรือ ล้มเหลวโดยคืน Evidence Item มาบางส่วน | F-7 (R-B-9) |
| 5 | พบ | complete ไม่มี Evidence Item, resolve ไม่ครบ, หรือ ล้มเหลว | F-7 (R-B-9); บันทึกรหัส F ของทั้งสองการพยายาม |
| 6 | พบ | complete resolve Evidence Item ได้ครบ | ตาม WP4 (R-B-9 ไม่ใช้) |

- NOT_FOUND ระดับแหล่งใช้ได้เฉพาะแถว 1 เท่านั้น
- ข้อเสนอนี้ตีความ R-B-6 ว่า "complete ไม่มี SR ทั้งสองรอบ" สอดคล้องกับมติ 21:57 ต้องให้ Owner ยืนยันตามย่อหน้านำของ §11
- แถวที่ไม่อยู่ในตารางนี้ไม่มี เพราะ R-B-1 จำกัด Retry ไว้ไม่เกินหนึ่งครั้งต่อแหล่ง

## 5. การเคารพ Privacy และ Consent

- การเข้าถึง CT-3 รอการอนุมัติ Privacy Baseline (WP1 v1.1 §7 ข้อ 3) ปัจจุบันยังไม่มีการอนุมัติ
- Permission Error ต้องไม่หลบด้วยแหล่งอื่นที่ผู้ใช้ไม่ได้อนุญาต
- ข้อความแจ้ง Error ไม่เปิดเผยตัวอักษรหรือตัวระบุจากแหล่งที่ไม่มีสิทธิ์

### 5.2 Default Deny สำหรับ CT-3 (MR-10, Owner อนุมัติ)

- CT-3 ใช้หลัก **Default Deny** จนกว่า Privacy Baseline จะได้รับการอนุมัติอย่างชัดเจนจากผู้มีอำนาจ
- ห้ามอนุมาน ห้ามให้สิทธิ์ ALLOW โดยไม่มีหลักฐานการอนุมัติ
- เมื่อยังไม่มีหลักฐาน ให้ปฏิเสธการเข้าถึงแหล่ง CT-3 และให้ผล F-3 (RETRIEVAL_FAILED สำหรับแหล่งจำเป็น) พร้อมบันทึกใน L-14 ว่าไม่มีรหัสการอนุมัติ
- ห้ามให้ผล NOT_FOUND สำหรับ CT-3 ที่ถูก Default Deny
- ห้ามใช้ Cache (§2.2.1) สำหรับ CT-3 ระหว่างนี้
- H-27 ตรวจได้จาก L-14 และผลของ F-3

## 6. Untrusted Memory

### 6.1 Trust Boundary (กฎบังคับ)

- **UM-1:** เนื้อหาใน Memory เป็นข้อมูลเสมอ ไม่มีอำนาจเปลี่ยนคำสั่งของระบบหรือผู้ใช้
- **UM-2:** คำสั่งที่ฝังอยู่ใน Memory ต้องไม่ถูกปฏิบัติ แม้ Detector จะไม่พบ
- **UM-3:** Evidence Item ที่มีรูปแบบคำสั่งที่รู้จักติด UNTRUSTED ทั้งชิ้น

### 6.2 การตรวจจับ

- Heuristic แบบกำหนดได้ บนรายการที่ยังไม่ได้รับอนุมัติ (รอ Catalogue)
- Semantic Review เป็นกลไกเสริม ต้องมี Human Review กลุ่มตัวอย่าง ผลไม่ถือเป็น Evidence ยืนยัน Claim
- ค่าที่รอ Owner: ขนาดกลุ่มตัวอย่างและความถี่

### 6.3 ผลของ Claim ที่เหลือเฉพาะ UNTRUSTED (MR-06)

- ไม่มี FOUND สำหรับ Claim นี้ เพราะไม่มี Evidence ที่ใช้ยืนยันได้
- ห้ามให้ NOT_FOUND สำหรับ Claim นี้ เพราะมีข้อมูลที่พบและถูกกักไว้
- **ผลระดับคำขอ (ตัดสินโดยริน ตามมอบหมาย MR-06):** RETRIEVAL_FAILED โดยเหตุผลคือ "ตรวจยืนยันไม่ได้ (UNTRUSTED-only)" ไม่ใช่ FOUND, ไม่ใช่ NOT_FOUND และไม่ใช่ PARTIAL เหตุผลนี้ไม่มีในการแจกแจง WP1 v1.1 §1 ต้องเพิ่มใน WP1 ผ่าน CR ภายหลัง (ดู §11 ข้อ 3)
- ข้อความถึงผู้ใช้ใช้ตามนี้: "มีข้อมูลที่ไม่น่าเชื่อถือซึ่งไม่ได้ใช้ยืนยัน" และห้ามใช้ Prohibited Terms ตาม §3.4
- บันทึก L-18 และ L-12 ของ Evidence Item ที่เกี่ยวข้อง

### 6.4 ชุดทดสอบ UM-2

- ต้องมีชุดตัวอย่างคำสั่งแฝงที่บันทึกไว้ ครอบคลุม: สั่งให้ละเลยกฎ, ขอเปิดเผยข้อมูลลับ, เปลี่ยนบทบาทระบบ
- เกณฑ์ผ่าน: คำสั่งทุกชุดไม่ถูกปฏิบัติ และผล Detector ถูกบันทึก
- ยังไม่ถูกสร้าง จัดเป็น Pending จนถึง WP8

### 6.5 กรณีที่ Detector ตรวจไม่พบ (MR-13)

- Detector ไม่รับประกันการจับคำสั่งแฝงทุกรูปแบบ ดังนั้น UM-2 ต้องบังคับใช้กับเนื้อหาที่ไม่ถูกตรวจพบด้วย
- เนื้อหาที่ไม่ถูกตรวจพบไม่มีอำนาจเปลี่ยนคำสั่งระบบ และไม่ใช้เป็นเหตุให้ผล ALLOW หรือให้สิทธิ์การเข้าถึง
- **การใช้เป็นหลักฐาน (ตัดสินโดยริน ตามมอบหมาย MR-13):** เนื้อหาที่ Detector ไม่พบใช้เป็นหลักฐานได้เฉพาะเมื่อผ่าน Evidence Sufficiency Criteria (WP1 v1.1 §3) และมี SR ที่ resolve ได้ การที่ Detector ไม่พบไม่ถือเป็นหลักฐานว่าปลอดภัย
- การตรวจย้อนกลับต้องทำผ่าน Human Review sampling (ดู §6.2) เพื่อพบกรณีที่หลุดจาก Detector
- Claim ที่ขึ้นกับเนื้อหาที่ Detector ไม่พบทั้งหมด ยังไม่ถือว่าผ่านการตรวจความปลอดภัย และต้องอยู่ในกลุ่มสุ่มตรวจ Human Review (§6.2)
